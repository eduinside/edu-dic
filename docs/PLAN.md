# 신규 앱 계획서 — 어린이 쉬운 사전 (가제)

> 작성일: 2026-08-26 · 상태: **계획(구현 착수 전)** · 운영: 1인 · 티어: 무료 유지 제약
> 정본 워크스페이스 규칙: [`../../CLAUDE.md`](../../CLAUDE.md) · 디자인 토큰 출처: [`edu-kit/app/styles/tokens.css`](../../edu-kit/app/styles/tokens.css)

유치원~초등 저학년이 (교사 지도 또는 스스로) **어려운 낱말을 입력하면, 대표 뜻풀이 + 관련 이미지 1장**을 큰 화면으로 보여 주는 사전 앱. 수업 시간 투사(projection)를 1순위 사용 맥락으로 설계한다.

| D21 | **홈 레이아웃 개편** | 랜딩은 검색창 + 4개 섹션(내가 찾은/즐겨찾기/자주 찾는/추천) 미리보기를 **세로 목록**으로(개수·순서는 D23 최종). 전체 목록·주제별 확장 탐색은 헤더의 **"나의 낱말사전"** 페이지로 이동(구조는 D26 최종). → §1.1, §1.3 |

| D22 | **동음이의어 처리** | krdict에 완전히 다른 뜻이 여러 표제어로 나뉜 경우(예: "배"=신체/선박/과일/곱절/단위 5개, 전부 초급) 대표 1개만 보여주지 않고 **정확 일치 표제어를 최대 4개까지 병렬 조회**해 `DictEntry.homographs`에 모두 담는다. 결과 화면에 전환 가능한 탭(첫 뜻풀이 미리보기)을 노출 — 뜻마다 이미지·소리·품사·등급이 독립적으로 바뀐다. **정렬은 krdict `sort=popular`를 그대로 신뢰**(등급 기반 재정렬 안 함, §2.2 실측 사유). → §2.8 |
| D24 | **이미지 3순위: 카카오→네이버 교체** | 카카오 이미지 검색을 **네이버 이미지 검색(NCP API Gateway)**으로 교체(`X-NCP-APIGW-API-KEY-ID`/`X-NCP-APIGW-API-KEY` 헤더 인증). safe-search 옵션이 문서에 없다는 한계는 동일 — krdict·encykorea 우선 원칙은 불변. → §3.1 |
| D25 | **동음이의어별 이미지·쉬운말 독립 처리** | (이미지) 동음이의어가 있으면 **encykorea는 전부 건너뛰고**(표제어만 보고 뜻을 구분 못 해 엉뚱한 뜻에 잘못 배정될 위험) 네이버만, 그것도 **뜻풀이 끝 낱말 힌트가 있을 때만** 검색(예: "배 과일"). 힌트가 "부분"·"단위"처럼 일반적이면(실측: "배"의 신체 뜻이 오히려 선박 사진으로 걸림) **검색 자체를 생략**하고 자리를 비운다(D27과 함께 — 틀린 사진보다 사진 없음이 안전). (쉬운말) `/api/simplify?h=` 로 동음이의어 인덱스를 받아 그 뜻만 변환·캐시 — 탭을 바꿔도 각자 독립적으로 "쉬운 말로"가 동작한다. → §2.7, §2.6 |
| D26 | **나의 낱말사전 개편** | "자주 찾는" 탭은 전역이 아니라 **"내가 자주 찾은 낱말"**(전체기간, 개인 로컬 집계 `edudic.searchCounts`)로 성격을 바꾼다(전역 인기는 랜딩에만 남음, D23). 목록은 **배지(칩) 형태**로 간결하게. 레이아웃은 **좌: 나의 활동(탭+배지) / 우: 낱말 익히기(주제 카드)** 반반. "낱말 익히기" 제목 옆 설정 버튼(수준·관심주제)은 **모달**로 열림. 페이지는 **`/my`** 전용 URL(검색어 경로와 충돌 방지를 위한 예약어) + `?tab=` 쿼리로 탭 상태도 공유 가능. → §1.3 |
| D27 | **자잘한 정확성/일관성 수정** | 답을 못 찾은 검색어(오타·미수록·차단)는 **"내가 찾은/자주 찾은" 기록에 남기지 않음**(성공 조회만 기록). 미수록 화면엔 즐겨찾기 별표 자체를 숨김. 상단 헤더는 "사전 그대로/쉬운 말로" 토글 유무와 무관하게 **높이 고정**(`min-h-14`). 큰화면 토글마다 **토스트 알림**(헤더 바로 아래). 뜻풀이 텍스트를 더 크고 굵게. 파비콘은 **투명 배경**(apple-touch-icon/OG는 브랜드 배경 유지). |

### 설계 원칙
- **★ 바로 찾아서 바로 보여준다 (이 프로젝트의 핵심).** 낱말 입력 → 결과 사이의 마찰을 0에 수렴시킨다. 로그인·모달·단계 없음. 구체 함의:
  - 진입 즉시 **검색창 자동 포커스**, 키보드 그대로 타이핑 시작.
  - 캐시 히트는 **체감 즉답**(목표 <100ms). 결과가 뜰 때 낱말·뜻·이미지가 **한 번에** 나타남(순차 로딩·레이아웃 밀림 금지 → 자리 미리 확보).
  - Enter/검색 → 곧바로 대형 결과. 부가 코너(최근·인기·즐겨찾기)는 결과를 가리지 않음.
  - 캐시 미스라도 "찾는 중" 상태를 즉시 보여 주고 결과로 자연 전환(빈 화면 금지).
- **정확성·안전성이 임계 경로다.** 대상이 유치원~초등 저학년 + 교실 투사이므로, "그럴듯하지만 틀린" 뜻·부적절 이미지는 절대 화면에 뜨면 안 된다. → v1은 **검수된 공신력 있는 사전(krdict)만** 신뢰. (속도를 위해 정확성을 타협하지 않는다 — 이 둘은 캐시로 양립.)
- **점진 성장(cache-on-demand).** 찾는 낱말을 그때그때 캐시에 적재 → 사전이 사용하면서 자란다. 초기 어휘수 부담 없음.
- **큰 화면 1순위.** 기본 UI가 곧 "발표 모드"에 가깝게. 낱말·뜻풀이 대형 타이포, 이미지 1장, 잡요소 최소.
- **기존 자산 재사용.** 디자인 토큰(edu-kit), AI 게이트웨이·2중 필터(byeduin `_ai.js` / `omni-moderation-latest`)를 3단계에서 그대로 붙인다. → [`byeduin-labs/docs/timely-ai-pattern.md`](../../byeduin-labs/docs/timely-ai-pattern.md)

## 1. 화면 구성 (웹, v1)

네이버 **사전 첫 화면**과 유사. 홈은 중앙 대형 검색창 + 아래 코너 섹션, 검색하면 대형 결과로 전환. 낱말 입력 → 결과의 마찰 0(§설계 원칙 ★).

### 1.1 홈 화면 (검색 전)
- **화면 중앙에 크고 뚜렷한 검색창** 하나(네이버 사전 첫 화면 느낌). 진입 즉시 **자동 포커스** → 바로 타이핑. 로고/타이틀은 검색창 위 최소한으로.
- **검색창 아래로 코너 섹션**이 순서대로 보임:
  1. **내가 찾은 낱말** (최근, localStorage)
  2. **즐겨찾기한 낱말** (★, localStorage)
  3. **자주 찾는 낱말** (전역 인기, D1 `edudic_popular`)
  4. **추천 낱말** (낱말 배우기 코너 — 첫 세트 "자연·계절", §6)
- 각 낱말 칩/카드를 **탭하면 즉시 검색 결과로**(재입력 없이). 비어 있는 섹션(예: 아직 최근 기록 없음)은 접거나 안내 문구로 대체.
- 저학년 대상: 큰 터치 타깃, 넉넉한 여백, 한글 위주(불필요한 영문·아이콘 남발 금지).

### 1.2 검색 결과 (메인)
- **대형 낱말** + 발음/품사(있으면) + **대표 뜻풀이 1개**(초급/중급 어휘등급 우선, 쉬운 정의 선택) + **관련 이미지 1장**.
- 뜻이 여러 개면 대표 1개만 크게, 나머지는 "뜻 더 보기"로 접어 둠(저학년 인지부하 최소).
- **발표 모드 토글**: 결과를 전체화면·초대형 타이포로. (교실 투사)
- 이미지 없는 낱말: 이미지 영역을 비우거나 낱말 이니셜 타일로 대체(빈 칸 어색함 방지). **없는 이미지를 웹에서 긁어오지 않음**(D4).

### 1.3 코너 데이터 소스 (홈 §1.1 섹션들)
| 홈 섹션 | 데이터 | 비고 |
|---|---|---|
| **내가 찾은 낱말** | localStorage(내 기기) | 최근 N개, 탭하면 재검색 |
| **즐겨찾기한 낱말** | localStorage(내 기기) | ★ 토글, 교사가 수업용으로 모아 두기 |
| **자주 찾는 낱말** | D1 `edudic_popular`(전역 익명 집계) | 인기 낱말 상위 N개(교실에서 함께 자주 찾는 말) |
| **추천 낱말** | 큐레이션 어휘 목록(§6, 첫 세트 자연·계절) | 클릭 → 검색 결과로 |

> 개인 섹션(내가 찾은/즐겨찾기)은 로그인 없이 **기기 localStorage**에만 저장 → 개인정보 최소 수집 원칙 준수. 전역 인기 집계만 D1에 익명 카운트.

## 2. 사전 데이터 — 한국어기초사전(krdict) (D3, D5)

### 2.1 왜 krdict인가
- **초등·학습자 눈높이**: 한국어기초사전은 학습자용 사전이라 표준국어대사전보다 정의가 쉽고 짧다. 표제어에 **어휘등급(초급/중급/고급)** 이 있어 저학년 적합어를 고를 수 있다.
- **이미지 포함·저작권 clean**: 멀티미디어(이미지·삽화)를 CC BY-SA 2.0(상업적 이용·출처표시)로 제공 → 교실 투사·배포 안전. (구글/네이버 웹 이미지 대비 결정적 장점)
- **무료 오픈 API**: 인증키 발급 후 사용. (공공데이터포털/krdict 등록)

관련 링크(구현 착수 시 최신 확인):
- 오픈 API 소개: https://krdict.korean.go.kr/kor/openApi/openApiInfo
- 사용 신청: https://krdict.korean.go.kr/kor/openApi/openApiRegister
- 공공데이터포털: https://www.data.go.kr/data/15105059/openapi.do

### 2.2 API 스펙 (공식 문서 확인 완료 2026-08-26 · 인증키 발급 완료)

> 검증 상태: 요청 파라미터·쿼터·응답 골격은 공식 openApiInfo 문서로 확정. **남은 M0 확인 1건** = `view` 응답에서 이미지 URL이 담기는 정확한 태그명(멀티미디어 링크 필드).

- **엔드포인트**
  - 검색(list): `GET https://krdict.korean.go.kr/api/search`
  - 상세(view): `GET https://krdict.korean.go.kr/api/view`
- **응답: XML 전용**(JSON 없음). CF Function에서 파싱→우리 JSON으로 정규화. CF Pages 무료 CPU(요청당 10ms) 고려해 **결과를 캐시**하고 핫패스는 캐시만 읽는다(§2.3).
- **일일 쿼터: 50,000회/일**(초과 시 에러코드 `010`). 넉넉하므로 캐시는 속도·안정성 목적(필수 방어선까진 아님). 초과 시 사용자에게는 "잠시 후 다시" 안내.
- **검색 `/api/search` 파라미터**
  | 파라미터 | 값 | 용도 |
  |---|---|---|
  | `key` | 32자리 hex | 인증키(서버 전용) |
  | `q` | UTF-8 검색어 | 필수 |
  | `sort` | `dict`\|`popular` | 사전순 / 빈도순 |
  | `part` | `word`\|`ip`\|`dfn`\|`exam` | 검색 범위(어휘/관용구/뜻풀이/용례) — 기본 `word` |
  | `level` | `level1`\|`level2`\|`level3` | 어휘등급 초급/중급/고급 필터(배열) |
  | `multimedia` | `0`~`6` | 매체 유형(사진·삽화·동영상·애니·음성…) 필터 |
  | `start` / `num` | 1–1000 / 10–100 | 페이지 시작·개수 |
  | `translated`/`trans_lang` | `y`\|`n` / `0`~`11` | 다국어(저학년 국어용이라 기본 미사용) |
- **상세 `/api/view` 파라미터**: `key`, `method`(`word_info`\|`target_code`), `q`(검색어 또는 target_code). 검색으로 표제어의 `target_code`를 얻어 `view`로 뜻·멀티미디어 상세를 가져오는 흐름.
- **응답 골격(공통)**: `<channel><total><item>` 반복, `<item>` 안에 `<word>`·`<definition>`·`<example>` 등. (상세의 멀티미디어/이미지 링크 태그는 M0 실호출로 확정)
- **대표 뜻/이미지 선택 규칙**은 §2.4.
- **인증키는 서버(Function/Secret)에만**. 프런트에서 krdict를 직접 부르지 않음(키 노출·CORS·쿼터 방어). → 키 주입 방식은 §2.5.

### 2.3 캐시·시드 전략 (어휘수 고민 해소)
```
[검색] → D1 edudic_dict_cache 조회
   ├ HIT  → 즉시 반환 (krdict 미호출)
   └ MISS → Function이 krdict 호출 → 파싱·정규화 → edudic_dict_cache 저장 → 반환
[오프라인 시드(선택)] 초등 기초어휘 목록(~1.5k~5k)을 배치로 미리 한 번 조회 → 캐시 워밍
```
- **온디맨드**로 실사용 낱말이 캐시에 쌓임 → 전체 사전을 미리 만들 필요 없음.
- **시드 워밍**(선택, 오프라인 스크립트 1회): 자주 쓸 기초어휘를 미리 캐시에 채워 첫 조회도 즉답·쿼터 절약. 시드 목록은 §6 큐레이션과 공유.
- 캐시 TTL: 사전 정의는 거의 안 변하므로 길게(수개월) + 수동 무효화. 이미지 URL만 만료 대비 재검증.

### 2.4 정규화 스키마(우리 표준형)
```ts
interface DictEntry {
  word: string;           // 표제어
  reading?: string;       // 발음/읽기
  pos?: string;           // 품사
  level?: '초급'|'중급'|'고급'|null;   // 어휘등급(대표 뜻 선택에 사용)
  senses: {               // 뜻풀이(대표부터 정렬)
    def: string;          // 쉬운 정의 문장
    example?: string;     // 예문(선택)
  }[];
  image?: {               // 대표 이미지 1장
    url: string;
    license: string;      // 'CC BY-SA 2.0'
    attribution: string;  // 출처표시 문구(화면 하단 소표기)
  } | null;
  source: 'krdict';
  fetchedAt: string;
}
```
> **출처표시(attribution) 필수** — CC BY-SA 조건. 이미지 하단에 작은 출처 문구를 항상 렌더.

### 2.5 인증키·환경변수 규약
- 변수명: **`KRDICT_API_KEY`**. (인증키 발급 완료 — 로컬 env 파일에 추후 입력 예정)
- **로컬 개발(wrangler)**: 프로젝트 루트 `.dev.vars` 에 `KRDICT_API_KEY=발급받은키` 한 줄. → **`.gitignore`에 `.dev.vars` 필수**(키 커밋 방지).
- **운영(CF Pages)**: 대시보드 환경변수 또는 `wrangler pages secret put KRDICT_API_KEY` 로 Secret 등록. 코드에서는 `env.KRDICT_API_KEY` 로 접근(byeduin `_ai.js`가 `env.*`를 읽는 패턴과 동일).
- 예시 파일 `.dev.vars.example`(키 없이 변수명만) 을 커밋해 셋업 안내.

## 3. 이미지·소리 (D4, D13)

### 3.1 이미지
- **1순위**: krdict 멀티미디어 이미지(위 스키마 `image`, `source: "krdict"`). 저작권 clean(CC BY-SA 2.0 KR)·아동 적합.
- **폴백(D13, 2026-08-26 추가)**: krdict에 대표 이미지가 없을 때만 **카카오(다음) 이미지 검색**으로 보완(`source: "kakao"`).
  https://developers.kakao.com/docs/ko/daum-search/dev-guide#search-image-info · `GET https://dapi.kakao.com/v2/search/image` · `Authorization: KakaoAK {REST_API_KEY}` · `sort=accuracy&size=1`.
  - **안전 가드**: krdict 이미지가 있으면 이 폴백을 절대 타지 않음. 검색어는 표제어 단어 그대로만 사용(문장 아님). 결과는 D1에 영구 캐시 → 같은 낱말은 항상 같은 이미지(재검증·수동 교체 쉬움).
  - **잔여 리스크**: 카카오 이미지 검색에는 안전검색(safe-search) 옵션이 공식 문서에 없음 — 미검수 웹 이미지가 노출될 수 있다. UI에서 `source==="kakao"`인 이미지는 "· 사진 검색 결과" 소표기로 krdict 검수 이미지와 구분 표시.
  - 구현: [`functions/lib/kakao.ts`](../../functions/lib/kakao.ts). 환경변수 `KAKAO_REST_API_KEY`(없으면 폴백만 생략, 앱은 정상 동작).
- 이미지도 없으면 이니셜 타일로 대체(빈 칸 어색함 방지).

### 3.2 소리(발음) — D13
- krdict `pronunciation_info`에도 이미지와 같은 패턴의 HTML 래퍼 페이지가 있고, 그 안 `<script>fnCmdPlaywer('audio', '/convert/.../SND..._.mp3', ...)`에 실제 mp3 경로가 있다(실호출로 확인, 2026-08-26).
- **라이선스가 이미지와 다르다**: 소리는 **CC BY-NC-ND 2.0 KR**(비상업적 이용만 허용, 2차저작물 금지) — 이미지의 CC BY-SA 2.0 KR(상업 허용)과 구분해서 표기해야 함. UI에서 소리 출처 문구를 이미지와 별도로 렌더(`DictEntry.audio.attribution`).
- UI: 낱말 옆 스피커 아이콘 버튼 → 클릭 시 `new Audio(url).play()`로 재생(네이티브 컨트롤 바 대신 저학년 터치에 맞는 큰 원형 버튼).
- 구현: `resolveAudioUrl()` in [`functions/lib/krdict.ts`](../../functions/lib/krdict.ts).

### 4.2 D1 (에듀링크 공용 DB · 전역·익명) — D12
> **에듀링크 D1(`edu-link-db`)을 공유**한다. 신규 DB 생성 없음. edu-dic 테이블은 **`edudic_` 접두사**로 분리하고, 에듀링크 테이블은 **읽지도 쓰지도 않는다**(완전 분리). 마이그레이션은 접두사 테이블만 추가하는 별도 파일로 관리하고, 같은 DB를 건드리므로 에듀링크 쪽과 번호·적용 시점을 조율(§9 파일 요약 참고).

```sql
-- 사전 캐시 (온디맨드 성장)
CREATE TABLE edudic_dict_cache (
  word       TEXT PRIMARY KEY,
  entry      TEXT NOT NULL,       -- 정규화 DictEntry(JSON)
  fetched_at TEXT NOT NULL
);
-- 자주 찾는 낱말(익명 집계 — 개인 식별 정보 저장 안 함)
CREATE TABLE edudic_popular (
  word    TEXT PRIMARY KEY,
  count   INTEGER NOT NULL DEFAULT 0,
  last_at TEXT
);
```
> `edudic_popular`는 낱말·횟수만 저장. IP·기기·사용자 식별자 저장 금지(개인정보 최소 수집). 바인딩은 에듀링크와 동일하게 `env.DB`. KV 캐시가 필요하면 에듀링크 `URL_CACHE`를 키 접두사로 공유하거나 edu-dic 전용 KV를 별도 검토(v1은 D1 캐시로 충분).

## 5. 필터링·안전 (D8)

AI가 없어도 **검색어 자체**가 부적절할 수 있고 그게 화면·인기목록에 노출되면 안 된다.

- **입력 프리필터(로컬 금칙어)**: byeduin `idea-lab.js`/`madang.js`의 로컬 금칙어 프리필터 패턴 재사용 → 명백한 비속어·부적절어는 사전 조회 없이 즉시 차단(부드러운 안내 문구). `popular` 집계에서도 제외.
- **사전 결과만 노출**: v1은 공신력 있는 사전 응답만 보여주므로 "생성된 위험 문장"은 원천적으로 없음.
- **moderation 대기(3단계용)**: OpenAI `omni-moderation-latest`(byeduin 재사용)는 AI 미지어 검색을 켤 때 2차 방어선으로 붙인다.
- 금칙어 사전은 byeduin과 공유/동기화 검토(중복 관리 회피).

## 6. "낱말 배우기 코너" · 초등 기초어휘

- **큐레이션 어휘 목록**: 초등 학년/주제(학교·자연·감정 등)별 기초 낱말 세트. 카드로 넘겨 보며 각 카드 클릭 → 검색 결과 재사용(별도 콘텐츠 저작 최소화).

- 저작 부담을 낮추기 위해 v1은 **1~2개 세트**로 시작, 반응 보며 확장.

## 8. 마일스톤

- **M0 — 발판**: 프로젝트 스캐폴드(Vite+React+Tailwind v4, edu-kit 토큰 복사), CF Pages/D1/wrangler 설정, krdict 인증키 발급.
- **M1 — 핵심 검색(웹 v1)**: `/api/lookup`(프리필터+캐시+krdict 정규화), 검색 결과 화면(대형 낱말·뜻·이미지 1장·발표 모드), localStorage 최근/즐겨찾기. → **여기까지가 최소 출시.**
- **M2 — 코너·집계**: 자주 찾는 낱말(D1 popular), 낱말 배우기 코너 1~2세트, 초등 기초어휘 시드 워밍 스크립트.
- **M3 — 다듬기**: 접근성(저학년 터치·큰 버튼·키보드), 오프라인/에러 UX("준비 중" 안내), 커스텀 도메인 연결.
- **M4 (2단계) — PC 스팟라이트 앱**: Tauri(전역 단축키·트레이·always-on-top 검색창)로 동일 API 재사용. → §9
- **M5 (3단계) — AI 미지어 검색(옵션)**: Timely + 2중 필터(로컬 금칙어 + moderation) + 출력 제약 프롬프트. 플래그로 on/off, 파일럿 검수 후 확대.

## 9. 2단계 — PC 스팟라이트 앱 (개요만)

- **후보 스택: Tauri v2**(Rust). 경량 바이너리, 전역 단축키, 시스템 트레이, always-on-top 창 → 맥 스팟라이트/알프레드류 UX에 적합. Electron 대비 용량·메모리 유리(1인 무료 운영 부합). 대상 OS는 교사 PC = **Windows** 우선.
- 웹 v1의 `/api/lookup`을 그대로 호출(프런트만 슬림 네이티브 검색 UI). → 로직 중복 없음.
- 배포/서명·자동업데이트는 공수가 크므로 v1 검증 후 착수. (school-portal-r2의 설치형 배포 선례 참고 가능)

## 12. 낱말 배우기 코너 — 첫 세트 후보

한 세트(약 20~40낱말)로 시작. **이미지 커버리지**가 관건 — krdict 삽화는 구체 명사(사물·동식물)에 몰려 있고 추상어(감정 등)는 이미지가 비는 경우가 많다. "바로 보여준다" 원칙상 **이미지가 잘 붙는 세트로 시작**하는 편이 체감 품질이 높다.

| 후보 | 내용 | 이미지 커버리지 | 메모 |
|---|---|---|---|
| **A. 학교생활** | 학교·교실·친구·수업·급식 등 | 중(구체 사물 위주면 양호) | 입학 초 적응, 즉시 유용 |
| **B. 자연·계절** | 동식물·날씨·계절 낱말 | **상**(삽화 풍부) | 관찰수업 연계, 첫 세트로 이미지 검증에 최적 |
| **C. 1~2학년 교과 기초어휘** | 교육과정 정렬 기초 낱말 | 중(혼합) | 범위 명확, 그러나 추상어 섞여 이미지 빈칸 가능 |
| **D. 마음·감정** | 감정·기분 낱말 | 하(추상어라 이미지 적음) | 인성·표현 교육엔 좋으나 "이미지 1장" 원칙과 상충 |

→ **확정: B(자연·계절)로 시작(D11).** 첫 세트로 krdict 이미지 실커버리지를 측정한 뒤 A(학교생활) 등으로 확장.

## 13. 향후 로드맵 (아직 미구현 — 방향만 기록)

- **관심 주제 사용자 추가 + AI 추천 낱말(2026-08-26 제안)**: 지금은 "낱말 익히기"의 관심 주제가 `WORD_SETS`(현재 "자연·계절" 1개)에 개발자가 미리 큐레이션한 것만 선택 가능(D26 설정 모달). 다음 단계로 **사용자(교사)가 새 주제를 직접 추가**할 수 있게 하고, 그 주제명을 AI(Timely, D17과 동일 게이트웨이)에 주면 **초등 저학년 수준의 추천 낱말 목록을 생성**해 그 주제의 "낱말 익히기" 카드로 채운다.
  - 접지(grounding) 원칙 유지: AI가 제안한 낱말은 그대로 노출하지 않고 **krdict에 실재하는지 검증된 것만**(D17-1/D17-3의 오타 교정·관련어 패턴과 동일 접근) 채택.
  - 저장 위치: 사용자 정의 주제이므로 로그인 없는 구조상 **기기 localStorage**에 저장하는 편이 자연스러움(D6 원칙과 일치). 다만 "다른 사용자와 공유"까지 가려면 서버 저장(D1)이 필요 — 필요성 재검토 후 결정.
  - 안전: 주제명 자체도 금칙어 프리필터(D8)를 통과해야 함.
